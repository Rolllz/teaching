Домашнее задание. Разворачиваем сетевую лабораторию.

Цель домашнего задания

    Научиться менять базовые сетевые настройки в Linux-based системах.

Описание домашнего задания

  Построить следующую архитектуру

    Сеть office1
    192.168.2.0/26 - dev
    192.168.2.64/26 - test servers
    192.168.2.128/26 - managers
    192.168.2.192/26 - office hardware
    Сеть office2
    192.168.1.0/25 - dev
    192.168.1.128/26 - test servers
    192.168.1.192/26 - office hardware
    Сеть central
    192.168.0.0/28 - directors
    192.168.0.32/28 - office hardware
    192.168.0.64/26 - wifi
    
    ```
    Office1 ---\
    ----> Central --IRouter --> internet
    Office2----/
    ```

Итого должны получится следующие сервера:
  
    inetRouter
    centralRouter
    office1Router
    office2Router
    centralServer
    office1Server
    office2Server

Теоретическая часть
  
    Найти свободные подсети
    Посчитать сколько узлов в каждой подсети, включая свободные
    Указать broadcast адрес для каждой подсети
    проверить нет ли ошибок при разбиении

Практическая часть

    Соединить офисы в сеть согласно схеме и настроить роутинг
    Все сервера и роутеры должны ходить в инет черз inetRouter
    Все сервера должны видеть друг друга
    у всех новых серверов отключить дефолт на нат (eth0), который вагрант поднимает для связи
    при нехватке сетевых интервейсов добавить по несколько адресов на интерфейс

В данном ДЗ был использован Debian 12.

Настройка Ansible производилась с использованием ролей для дальнейшего масштабирования архитектуры. Для каждого роутера, для серверов, а также для всех хостов есть свои плейбуки, выделенные в отдельные роли.

Так как в Debian в большинстве случаев используется Network Manager, а не netplan, было принято решение использовать его. Ну и для него не было инструкций, как в случае с netplan)

Абсолютно все настройки были произведены с помощью модулей Ansible.

После настройки сетевых интерфейсов было необходимо перезапустить службу NetworkManager, попытался сделать это с помощью handler, однако он срабатывает после всех тасков, перечисленных в плейбуке. Пришлось вывести это действие в отдельную задачу.

Настройку iptables можно также сделать с помощью модулей Ansible, но такие действия требуют повышенных привилегий, как и действия с NetworkManager. Данная проблема решается с помощью установки флага ```ansible_become: true``` в файле inventory для тех хостов, на которых необходимо произвести требуемые действия.

Для того, чтобы Vagrant прочитал файл ansible.cfg и передал его для провижна в Ansible, необходимо положить его в директорию с Vagrantfile. Однако Ansible в новых версиях ругается на него, из-за чего нужно напрямую указывать переменную с расположением файла. Например:

```
export ANSIBLE_CONFIG=/path/to/ansible/config
```

Таким образом, перезапишется путь до стандартного конфигурационного файла, лежащего по пути ```/etc/ansible/ansible.cfg```.

Однако в Vagrantfile предусмотрены настройки для Ansible, благодаря чему необходимость вручную указывать путь до этого файла отпала.
