Домашнее задание. Разворачиваем сетевую лабораторию.

Цель домашнего задания

    Научиться менять базовые сетевые настройки в Linux-based системах.

Описание домашнего задания

  Построить следующую архитектуру

    Сеть office1
    192.168.2.0/26 - dev
    192.168.2.64/26 - test servers
    192.168.2.128/26 - managers
    192.168.2.192/26 - office hardware
    Сеть office2
    192.168.1.0/25 - dev
    192.168.1.128/26 - test servers
    192.168.1.192/26 - office hardware
    Сеть central
    192.168.0.0/28 - directors
    192.168.0.32/28 - office hardware
    192.168.0.64/26 - wifi
    
```
Office1 ---\
----> Central --IRouter --> internet
Office2----/
```

Итого должны получится следующие сервера:
  
    inetRouter
    centralRouter
    office1Router
    office2Router
    centralServer
    office1Server
    office2Server

Теоретическая часть
  
    1.    Найти свободные подсети
    2.    Посчитать, сколько узлов в каждой подсети, включая свободные
    3.    Указать broadcast адрес для каждой подсети
    4.    Проверить, нет ли ошибок при разбиении

Практическая часть

    1.    Соединить офисы в сеть согласно схеме и настроить роутинг
    2.    Все сервера и роутеры должны ходить в инет черз inetRouter
    3.    Все сервера должны видеть друг друга
    4.    у всех новых серверов отключить дефолт на нат (eth0), который вагрант поднимает для связи
    5.    При нехватке сетевых интервейсов добавить по несколько адресов на интерфейс

В данном ДЗ был использован Debian 12.

Настройка Ansible производилась с использованием отдельной роли для inetRouter. Настройка всех остальных машин была произведена в общем плейбуке.

В Debian 12 по умолчанию устанавливается Network Manager, и было бы логично произвести настройку через него. Однако в боксе все урезано, и есть старый добрый iproute2.
Есть netplan, который можно установить так же, как и Network Manager, однако для него уже есть инструкция, что не очень интересно с точки зрения выполнения ДЗ.

Если работать с Network Manager, то каким бы способом я ни пытался сохранить маршруты, Vagrant каждый раз при релоаде перенастраивал интерфейсы согласно Vagrantfile через /etc/network/interfaces, и даже если в NetworkManager были настройки маршрутов, они не применялись. Поэтому было принято решение работать с iproute2.

Принцип тот же, что и с netplan в методичке: на каждую машину скопировать файл с его маршрутами. Только вместо конфигов будут файлы постконфигурационной настройки маршрутов через скрипты в папке /etc/network/if-up.d. Таким образом, при каждом перезапуске маршруты будут настраиваться заново, и всё будет хорошо.

Настройку iptables можно сделать с помощью модулей Ansible, но такие действия требуют повышенных привилегий, как и действия с сетевыми утилитами. Данная проблема решается с помощью установки флага ```ansible_become: true``` в файле inventory для тех хостов, на которых необходимо произвести требуемые действия.

Для того, чтобы Vagrant прочитал файл ansible.cfg и передал его для провижна в Ansible, необходимо положить его в директорию с Vagrantfile. Однако Ansible в новых версиях пропускает его якобы из соображений безопасности, мол, его может кто-нибудь подменить, из-за чего нужно напрямую указывать переменную с расположением файла. Например:

```
export ANSIBLE_CONFIG=/path/to/ansible/config
```

Таким образом, путь до стандартного конфигурационного файла, лежащего по пути ```/etc/ansible/ansible.cfg```, будет изменён.

Однако в Vagrantfile предусмотрены настройки для Ansible, благодаря чему необходимость вручную указывать путь до этого файла при каждом запуске Vagrant отпала.
